### 1.0 Project scaffold with the Docxodus engine in our own Web Worker

**Depends on:** nothing.

**Specs:**

- `vite.config.ts` `base` comes from an env var (`BASE_PATH`, default `/`), so the same build works locally and under `/<repo>/`.

- `ChangeItem`:
  ```ts
  interface ChangeItem {
    id: string;                 // stable: the first engine revision id it contains (ids are deterministic per inputs + engine version)
    kind: 'inserted' | 'deleted' | 'replaced' | 'formatting' | 'moved' | 'paragraph';
    revisionIds: string[];      // all engine revisions this item decides (incl. folded paragraph marks)
    removedText: string;        // '' when none
    addedText: string;          // '' when none
    description?: string;       // formatting: from the HTML title, e.g. "Bold removed, Font changed"
    location: { scope: 'body' | 'footnote' | 'endnote' | 'table'; noteId?: string };
    wordDelta: { removed: number; added: number };
    order: number;              // document order index
    anchors: string[];          // affectedAnchors unids, for scrolling and range
  }
  ```
- Item rules (PRD §7.2 step 3). Formatting revisions are interleaved with content revisions in the engine list, so apply the next three rules to the sequence of **non-formatting** revisions:
  - Paragraph marks: a `paragraph_mark` revision whose `text` is only `¶` characters joins the previous or next content revision in that sequence if they share an affected anchor (prefer previous); otherwise it becomes a `paragraph` item. A `paragraph_mark` revision with other text is an ordinary `deleted`/`inserted` item.
  - Replaced: a `content_delete` and a `content_insert` that are neighbours in that sequence, in **either order**, and share an affected anchor become one `replaced` item. Pair greedily left to right; a revision joins at most one pair.
  - Moves: one `move` revision → one `moved` item (the entry covers both halves).
  - Formatting: every `type: "format"` revision (`rPrChange`, `pPrChange`, `sectPrChange`) → one `formatting` item.
- `DocIndex` (`src/model/docIndex.ts`, main thread, native `DOMParser` on the rendered HTML):
  `{ blocks: { unid, scope: 'body' | 'fn' | 'en', inOriginal: boolean }[], bodyParagraphs: string[] /* unids of Original body paragraphs, in order */, noteRefs: Map<noteId, unid /* body paragraph */> }`.
  Blocks come from elements with `data-anchor` (kind/scope from `data-source-anchor-id`, e.g. `p:body:…`, `p:fn:…`); `inOriginal` = the block is not wholly inside `ins`/`.rev-move-to`; note refs from `a.footnote-ref[data-footnote-id]` (check the endnote equivalent on a fixture).
- Range (`src/model/range.ts`): `detectTrailingRegion(items, index)` returns the index (in `bodyParagraphs`) of the first anchor of the delete-type body item whose anchors include the **last** Original body paragraph, or `null` (refined in 4.20: only when that paragraph is wholly deleted, and the first *wholly deleted* anchor). Do not require it to be the last item. `classify(items, index, endPoint | null)` returns `inRange` / `outOfRange` per item; note items follow the paragraph that references the note; an item spanning the end point is out of range.

  | Markup | Rewrite |
  |---|---|
  | `w:ins` around runs | rename to `w:del`; `w:t` → `w:delText`; `w:instrText` → `w:delInstrText` |
  | `w:del` around runs | unwrap (keep children); `w:delText` → `w:t`; `w:delInstrText` → `w:instrText` |
  | `w:rPrChange` | replace the parent `w:rPr` children with the `w:rPrChange/w:rPr` children; drop `w:rPrChange` |
  | `w:pPrChange` | replace the `w:pPr` children with: the `w:pPrChange/w:pPr` children **first**, then the existing `w:rPr` (paragraph mark), then the existing `w:sectPr`. Wrong order still gives the right text but fails `verifyDeliverable` (schema) — seen in the prototype |
  | `w:sectPrChange` | replace the `w:sectPr` children with: existing `w:headerReference`/`w:footerReference` first, then the `w:sectPrChange/w:sectPr` children |
  | paragraph mark `w:pPr/w:rPr/w:ins` | rename to `w:del` |
  | paragraph mark `w:pPr/w:rPr/w:del` | remove the element |
  | `w:moveFrom` | unwrap, `w:delText` → `w:t`; remove matching `w:moveFromRangeStart/End` |
  | `w:moveTo` | rename to `w:del`, `w:t` → `w:delText`; remove matching `w:moveToRangeStart/End` |
  | `w:trPr/w:ins` | rename to `w:del` (the inserted row will be removed) |
  | `w:trPr/w:del` | remove the marker (the deleted row stays); also apply the `w:del`-around-runs rule to the row's content |
  | `w:cellIns` | rename to `w:cellDel` |
  | `w:cellDel` | remove the marker |
  | `w:tblPrChange`, `w:trPrChange`, `w:tcPrChange`, `w:tblPrExChange` | replace the parent `w:tblPr`/`w:trPr`/`w:tcPr`/`w:tblPrEx` children with the stored old ones (keeping any revision markers of the parent, e.g. `w:trPr/w:ins`, and schema order); drop the change |
  | `w:tblGridChange` | replace the `w:tblGrid` children with the `w:tblGridChange/w:tblGrid` children; drop the change |
  | anything else | throw `UnsupportedRevisionError(revisionId, family)` |
